# 命令注册与调度

licon 使用 **Commander.js v12.x** 作为 CLI 框架。入口文件 `src/index.ts` 既是程序入口点，也是整个命令系统的**路由中心**——所有命令都在这里注册、配置参数与选项，并转发到对应的处理模块。当用户无参数运行 `licon` 时，它还负责自动跳转到首次配置或交互模式。

## 程序基础信息

Commander 实例在文件头部创建，配置三项元数据：

```typescript
const program = new Command();

program
  .name('licon')
  .description('CLI tool for fetching Lucide icons - designed for AI agents and developers')
  .version('1.0.0');
```

- **`name`**：设置命令名称，决定 `--help` 输出的标题行。
- **`description`**：简短描述工具用途，出现在 `--help` 摘要区。
- **`version`**：当前版本号，通过 `licon --version` 读取。注意此版本号与 `package.json` 中的 `"version": "1.0.1"` 略有滞后，两者需手动同步。

## 命令注册全景

注册模式遵循统一的 Commander 惯用法：`.command(name)` → `.description(...)` → `.option(...)`（可选）→ `.action(handler)`。每个 `action` 回调先读取配置，再转发到对应的模块函数。

| 命令 | 参数 | 选项 | 处理函数 | 模块文件 |
|---|---|---|---|---|
| `setup` | 无 | 无 | `setupCommand()` | [`src/commands/setup.ts`](src/commands/setup.ts) |
| `get` | `<names...>`（变长） | `-f, --format <type>` | `getCommand(names, options, config)` | [`src/commands/get.ts`](src/commands/get.ts) |
| `save` | `<name>` | `-o, --output <path>` | `saveCommand(name, options, config)` | [`src/commands/save.ts`](src/commands/save.ts) |
| `list` | 无 | 无 | `listCommand(config)` | [`src/commands/list.ts`](src/commands/list.ts) |
| `search` | `<query>` | `-n, --limit <num>`（默认 `'5'`），`-v, --verbose` | `searchCommand(query, options, config)` | [`src/commands/search.ts`](src/commands/search.ts) |
| `cat` | `<category>` | 无 | `catCommand(category, config)` | [`src/commands/cat.ts`](src/commands/cat.ts) |
| `convert` | `<name>` | `-f, --format <format>`，`-o, --output <path>` | `convertCommand(name, options, config)`（异步） | [`src/commands/convert.ts`](src/commands/convert.ts) |
| `upgrade` | 无 | 无 | `upgradeCommand()` | [`src/commands/upgrade.ts`](src/commands/upgrade.ts) |
| `interactive` | 无 | 无 | `interactiveCommand(config)`（异步） | [`src/commands/interactive.ts`](src/commands/interactive.ts) |
| `categories` | 无 | 无 | 内联实现 | 无独立模块 |

## 参数与选项的惯用法

Commander v12 支持两种典型模式，licon 中都有体现：

### 位置参数

- **必选参数**：用尖括号标注，如 `<name>`、`<query>`、`<category>`。
- **变长参数**：`<names...>` 允许用户传入一个或多个图标名，Commander 自动解析为字符串数组。`get` 命令还额外兼容了空格或逗号分隔的单字符串输入，在 `getCommand` 内部做二次拆分。

```typescript
//　变长参数声明
program.command('get <names...>')
// 内部二次拆分（处理 'alarm home' 或 'alarm,home'）
if (names.length === 1 && (names[0].includes(' ') || names[0].includes(','))) {
  names = names[0].split(/[ ,]+/).filter(n => n);
}
```

[来源](src/index.ts#L18-L24) | [来源](src/commands/get.ts#L38-L40)

### 选项

- `--limit <num>` 的默认值 `'5'` 以字符串形式传入，因为 Commander 默认将选项值视为字符串。
- `--verbose` 为布尔开关，无参数值。
- `--format` 的值不设枚举校验，由下游模块自行处理 `svg` / `json` / `png` / `webp`。

[来源](src/index.ts#L34-L37) | [来源](src/index.ts#L55-L58)

## 自动跳转逻辑：无参数时的入口路由

`src/index.ts` 最关键的架构决策在文件底部：

```typescript
if (process.argv.length === 2) {
  const config = getConfig();
  if (!configExists()) {
    console.log('🔧 First time setup required.\n');
    setupCommand();
  } else {
    interactiveCommand(config);
  }
} else {
  program.parse(process.argv);
}
```

当用户只输入 `licon`（无子命令和选项）时，`process.argv` 仅包含 node 路径和脚本路径两个元素。此时不走 Commander 的 `parse`，而是手动路由：

1. **配置不存在**（首次使用）→ 自动进入 [`setup`](快速开始.md) 引导，提示用户配置 Lucide 仓库路径。
2. **配置已存在** → 自动进入[交互模式](交互模式.md)，打开图标选择器。

这个设计让新手无需记忆任何命令即可完成初始化，也让日常使用者直接进入交互式浏览体验。

[来源](src/index.ts#L79-L89)

## 配置读取模式

注意观察：**每个命令的 `action` 回调内部都调用 `getConfig()`** 而非在模块外部注入。Commander 的 `action` 闭包捕获的是当前状态，每次执行都重新读取 `~/.licon.json`，确保配置变更后立即生效。

存在一个例外：`categories` 命令没有独立模块，它直接在 `action` 回调中完成所有逻辑，包括同步读取 `categories/` 目录。这种内联方式适合逻辑简单且不会复用的命令。

## 导入顺序的"后置"问题

文件中存在一个不常见的代码排布：`import fs from 'fs'` 和 `import path from 'path'` 出现在所有 Commander 注册代码**之后**（第 78-79 行），而不是文件顶部。这得益于 ES Module 的**静态提升**（hoisting）——所有 `import` 声明无论写在哪一行，都会在模块执行前被提前处理，运行时不会报错。

虽然技术上可行，但这种写法容易让人误以为 `fs` 和 `path` 在之前的代码中不可用。`categories` 的 `action` 回调用到了 `fs` 和 `path`，但因为它们是延迟执行的，实际运行时导入已经完成。

[来源](src/index.ts#L78-L79)
