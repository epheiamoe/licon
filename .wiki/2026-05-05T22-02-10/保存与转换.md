下面围绕 `save` 和 `convert` 两个命令，讲解它们各自的职责、实现要点以及 `--output` 参数的使用方式。

---

# 保存与转换

当你需要将图标从 Lucide 仓库**搬到本地磁盘**，或者将其从 SVG **光栅化为图片格式**时，`licon save` 和 `licon convert` 就是你要用的两个命令。它们解决的是同一类问题——图标输出到文件——但分工不同。

---

## 两条命令的分工

| 命令 | 核心职责 | 输出格式 | 后端依赖 |
|------|----------|----------|----------|
| `licon save` | 从 Lucide 仓库**原样复制** SVG 文件 | `.svg` | 无 |
| `licon convert` | 读取 SVG 并**转换为**指定格式 | `.svg` / `.png` / `.webp` | PNG/WebP 需 `sharp` |

`save` 是纯文件复制，零依赖；`convert` 在格式为 `svg` 时也走复制路径，但 `png` 和 `webp` 需要借助 [sharp](https://sharp.pixelplumbing.com/) 库完成光栅化。[来源](src/commands/save.ts#L6-L32)，[来源](src/commands/convert.ts#L10-L77)

---

## licon save：文件级复制

`save` 的逻辑非常直接：从配置的 Lucide 仓库 `icons/` 目录中找到对应的 `.svg` 文件，读取后写入目标目录。

```bash
licon save settings
# Saved: /current/dir/settings.svg

licon save settings --output ./my-icons
# Saved: ./my-icons/settings.svg
```

源码中，核心步骤只有四行：

1. 拼接源路径：`path.join(iconsDir, \`${name}.svg\`)`
2. 检查源文件是否存在，不存在则报错退出
3. 读取 SVG 文本：`fs.readFileSync(iconPath, 'utf-8')`
4. 写入目标文件：`fs.writeFileSync(destPath, svg)`

如果 `--output` 指定的目录不存在，命令会自动创建（`mkdirSync` 带 `recursive: true`）。[来源](src/commands/save.ts#L13-L31)

`save` 只接受**单个图标名**，不支持批量操作。如果需要一次获取多个图标的 SVG 代码直接嵌入（而非写入文件），应使用 `[获取 SVG](获取-svg.md)` 中的 `licon get` 命令。

## licon convert：格式转换

`convert` 在 `save` 的基础上增加了**格式选择**和**光栅化**能力：

```bash
licon convert settings --format svg
# 纯复制，等价于 save

licon convert settings --format png --output ./icons
# 需要 sharp，输出 PNG

licon convert settings --format webp --output ./icons
# 需要 sharp，输出 WebP
```

### 三种格式的处理路径

`convert` 内部以 `options.format` 为分支：

- **`svg`**：走文件复制路径，与 `save` 完全一致，读取 UTF-8 文本后写入 `.svg` 文件。[来源](src/commands/convert.ts#L36-L41)
- **`png`** / **`webp`**：读取原始 Buffer，调用 `sharp(svg).png().toBuffer()` 或 `sharp(svg).webp().toBuffer()` 进行光栅化，再将 Buffer 写入目标文件。[来源](src/commands/convert.ts#L55-L60)
- **其他格式**：输出 "Unsupported format" 错误并退出。[来源](src/commands/convert.ts#L61-L64)

### 可选依赖 sharp 的处理

这是 `convert` 命令最有意思的设计点。`sharp` 是一个体积庞大的原生模块，licon 将其列为**可选依赖**——如果不安装，`convert --format png` 会友好地提示：

```
⚠️  sharp is not installed. Cannot convert to PNG/WebP.
   Install with: npm install sharp
   Or use SVG output instead: --format svg
```

实现上，`sharp` 通过 `require()` 在 try/catch 中加载。如果未安装，变量 `sharp` 保持 `null`，后续检查到 `null` 时输出提示并退出。[来源](src/commands/convert.ts#L10-L14)，[来源](src/commands/convert.ts#L43-L48)

---

## --output 参数

`save` 和 `convert` 都支持 `-o, --output <path>` 参数，语义完全一致：

- **默认值**：`process.cwd()`，即当前工作目录。
- **目录不存在时**：自动递归创建，无需用户提前建好。
- **路径可以是相对路径或绝对路径**：Node.js 的 `path.join` 会正确处理。

```bash
# 当前目录
licon save home

# 相对路径
licon save home --output ./icons/home

# 绝对路径
licon save home --output /tmp/icons
```

目标文件名为 `{图标名}.{格式后缀}`，例如 `settings.svg`、`settings.png`。[来源](src/commands/save.ts#L19-L21)，[来源](src/commands/convert.ts#L31-L35)

## 场景案例

### 前端项目批量保存图标

假设你正在搭建一个组件库，需要将常用图标放入 `src/assets/icons/` 目录：

```bash
# 先搜索确认图标名
licon search arrow

# 逐个保存到项目目录
licon save arrow-right --output src/assets/icons
licon save arrow-left --output src/assets/icons
licon save arrow-up --output src/assets/icons
```

### 生成 PNG 供非浏览器环境使用

在 Electron 或 Node.js 后端中可能需要直接使用图片而非 SVG：

```bash
# 先安装 sharp（一次性）
npm install sharp

# 将图标转为 PNG
licon convert settings --format png --output ./images
licon convert user --format png --output ./images
```

### SVG 原样存档

即使目标格式是 SVG，`convert --format svg` 和 `save` 的行为一致，你可以根据语义偏好选择命令——需要复制用 `save`，可能在多种格式间切换用 `convert`。
